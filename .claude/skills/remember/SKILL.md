# Remember — memory is written with the user's OK

## When
- at the end of a job or of a long session;
- when the user corrects something ("no, I want dates written out in full") → it is a
  preference;
- when a mistake or a hitch happens → it is a lesson;
- when new data about clients, suppliers or offices comes up.

## How
1. Prepare **at most 5 proposals**, numbered, one line each, with the destination:
   > 1. Preference: dates written out in full (15 October 2026) → `decisions/preferences.md`
   > 2. Client: Smith Ltd always wants the quote before starting → `contacts/clients.md`
2. Ask: "Shall I save them all? Or tell me the numbers to drop or correct."
3. Save only the approved ones, **in the user's language**:
   - a short sentence, with the date (`(YYYY-MM-DD)`) and, if useful, the job it came from;
   - **before adding, search** whether something similar already exists: update that entry
     instead of duplicating it; if the new one contradicts an old one, replace it and say
     so;
   - if the destination file does not exist, create it and add it to `memory/INDEX.md`.
4. Without asking, also update the job's `JOB.md` (status, decisions) and the counter in
   `memory/job-types.md`.

## What does NOT go into memory
- what is already in the job card or in the documents;
- details that only matter today;
- sensitive data (health, ID documents, bank details, judicial data);
- passwords, access codes, PINs: never, anywhere.
